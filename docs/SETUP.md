# Setup and verified bootstrap commands

## Environment and resolution

Recommended Python 3.12; declaration allows 3.11–3.14 but only 3.12 was tested.
Node must satisfy Vite's runtime requirement (20.19+ on the 20 line or 22.12+);
Node 24.19.0 / npm 11.17.0 is the local verification environment. Python 3.14 in
the user's Anaconda environment was not modified. The available Codex bundled
Python 3.12.14 created this repository's `.venv`.

`backend/requirements.lock.txt` is a genuine pip freeze of the resolved Windows
Python 3.12 core/dev dependencies, excluding the editable project itself. It is
a version-pinned environment snapshot, without wheel hashes or a cross-platform
compatibility guarantee. `frontend/package-lock.json` is generated by npm.
Integration alone updates declarations and locks. Astropy is optional
(`backend[astronomy]`), was not installed, and is not imported by the bootstrap.
No trained-model dependency is included.

## Windows PowerShell

From the repository root, if Python 3.12 is installed with the launcher:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e ./backend
.\.venv\Scripts\python.exe -m pytest -q -c backend/pyproject.toml
.\.venv\Scripts\python.exe scripts/check_imports.py
.\.venv\Scripts\python.exe scripts/check_docs.py
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

The launcher has no registered Python on this machine. The virtual environment
has already been created with the bundled runtime using:

```powershell
& 'C:\Users\subha\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e './backend[dev]'
```

These absolute paths describe this machine only; teammates should use their own
Python 3.12. Invoke the venv executable directly; activation is optional.

In a second terminal:

```powershell
cd frontend
npm ci
npm run build
npm run dev
```

`npm install` resolved the initial lock. Use `npm ci` subsequently. Vite binds
127.0.0.1 and proxies `/api` to `http://127.0.0.1:8000`; no CORS wildcard is
required. Backend health is also available at `http://127.0.0.1:8000/api/health`.
OpenAPI describes only the implemented health route. `.env.example` is safe
future configuration documentation; the bootstrap does not load `.env`.

In `frontend/`, run `npm ci`, `npm run build`, `npm run dev`. Resolve on your
platform when the Windows snapshot is unsuitable; record any lock changes.

## Troubleshooting and offline preparation

If health is unavailable, start Uvicorn from the installed venv and check port
8000; the UI offers refresh. Use OpenCV headless and avoid mixing environments.
Install/cache dependencies before an offline demo. The current readiness UI can
run locally, but no offline scientific demo exists until T02–T12. Do not change
global PowerShell execution policy to activate a venv.

In this session sandbox temp-file permissions and npm DNS initially blocked
installation. Authorized retries completed. Record actual checks and failures
in [STATUS](STATUS.md); never treat a help command as algorithm completion.
