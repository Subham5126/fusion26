## Contracts consumed / produced

- **Consumed:**
  - `app.schemas.result.Track` & `app.schemas.result.TrackPoint` produced by T04 `Tracker`.
  - Timing basis: either `second` (`px/s`) when timestamps are valid and monotonic, or `frame` (`px/frame`) when timestamps are absent (`null`).
- **Produced:**
  - `app.schemas.result.TrajectoryEstimate` attached to `track.trajectory`.
  - Estimates: `vx`, `vy`, `speed`, `speed_unit`, `fit_rmse_px`, `observations_used`, `predictions` (2-frame future extrapolation).
  - Explicit prediction rules: Future extrapolated points have `point_type == "extrapolated"` and `detection_id is None`. No fabricated detection IDs.
  - Strict minimum observations: Requires at least 3 observed points. Tracks with $< 3$ observations receive `track.trajectory = None`.

## Reproducible sample / usage

```python
from orbittrace.trajectory.fit import fit_trajectory

# For each track finalized by Tracker:
fitted_trajectory = fit_trajectory(
    track=track,
    extrapolate_steps=2,
    coordinate_frame="reference_frame_0",
)
track.trajectory = fitted_trajectory
```

## Known limitations / notes for Lead

- Assumes constant-velocity motion model ($x(t) = x_0 + v_x t$, $y(t) = y_0 + v_y t$) via ordinary least squares (`np.linalg.lstsq`).
- Does not claim Keplerian orbit determination or 3D physical speed.
- `tests/tracking/test_pipeline_integration.py` provides Member 1 with the exact pattern to construct `AnalysisResult` from pipeline outputs.
